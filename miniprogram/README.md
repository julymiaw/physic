# 干涉条纹计数 · 微信小程序

在微信开发者工具中导入此目录，AppID为`wx0bf8226dfc306d3a`。首版在本地完成计算，无npm构建、云服务、AppSecret或上传密钥依赖。已接入WASM，不使用模拟计数。

首页为暗色、无滚动工具布局：相机占主要区域，底部显示五路亮度曲线、四路共同暗心零点相位、整数净计数及状态。圈选、标定/开始测量/停止/再次测量、信号开关和帮助为主要按钮。首次说明使用暗色弹窗，之后可按`?`查看；没有常驻说明段落。关闭信号区会改变预览布局，需重新圈选。开启帮助会关闭相机，测量中帮助和信号开关禁用；圈选和切后台会中断当前段。

开启相机后按住拖动圈选整个光屏，点标定，连续单向移动使中心暗纹至少出现两次。约2秒后开始尝试建模，每秒最多一次，最长10秒或256帧；成功后进入“待开始”，继续跟踪但不计数，标定方向作为正方向。停下旋钮、记录起始读数后点击“开始测量”，以最近有效帧的相位为测量零点。起点不足一个周期的部分不会作为完整一圈；整数表示相对起点的完整净周期，连续周期与余量保存在结果元数据中。失败显示“标定失败”和“—”，不会捏造计数。点击“停止”后进入“确认中”，最多再处理4个有效观测，只确认停止点击之前已提交的帧，随后固定计数，不累计之后的运动。学生应先停下旋钮，再停止计数并记录终止读数。信号持续有效时可直接“再次测量”，只更换测量零点，复用标定；等待期间的运动不写入上一组结果。

重选、相机中断、帧间隔过大、相位不可靠，会冻结可信累计值并显示不完整。重新标定是新段，不能恢复之前丢失的信息。

相机回调实际宽高用于中心裁剪的预览映射；圈选区域扩展1.5倍并面积积分到96像素红通道图，计数区域64像素。预览/原始帧的方向与裁剪对应关系仍需手机对照验证。当前Iriun→开发者工具实测回调480×640，改变显示尺寸未改变它。

采样点、曲线和相位箭头使用同一组低亮度颜色。箭头展示实际模型相位，不能视为理想无噪声的共同角度。仅保留最新一个待处理相机帧，跳帧后的接收间隔参与连续性检查；相机接收时钟不是曝光时间。高精度时钟不可用时改用带倒退检查的系统接收时间，间隔异常仍由核心拒绝；时钟来源记录在测量元数据中。曲线显示最近约2秒、最多150个已收到观测；信号图和状态约10Hz刷新，核心逐个处理实际有效观测。

现有`wasm/fringe.wasm`由Emscripten6.0.12构建；以WASM异常处理保留拒绝路径，当前开发者工具已通过，但较旧手机微信的兼容性还需测。短暂反向和返回仍由相位连续性及净计数处理，没有删除成对事件或忽略反转。

共享输入缓冲区避免逐像素调用C接口，初始64MiB、最多128MiB线性内存。画面不保存或上传；停止/中断保存上一测量段的计数、完整性及最多512条事件元数据，截断会记录标记。最近不完整段单独保留，后续成功段不覆盖该事实；状态按钮可查看，当前计数只代表当前段。
