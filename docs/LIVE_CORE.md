# 流式计数接口

唯一相位模型与事件判定在 `research/phase_core.h`；Native文件回放与 `core/live_counter.h` 共用。`research/screen_tracker.h`保持原样。重构后两段真实录像的Native逐帧结果与冻结结果所有对应字段完全相同。

`core/live_api.cpp`提供C接口，Node和微信调用同一份WASM：

| 接口 | 用途 |
|---|---|
| `fc_create` / `fc_destroy` | 创建、销毁句柄 |
| `fc_input` | 9216个float32的96×96灰度/红通道输入缓冲区 |
| `fc_reset(handle, offset_x, offset_y)` | 显式开始新段，默认计数坐标位于带余量图的(16,16) |
| `fc_calibrate(handle, seconds, source_frame)` | 提交标定帧，最多256帧或10秒 |
| `fc_start` | 用已有标定建立模型；失败保留原始标定帧供后续重试 |
| `fc_arm` | 标定成功后转入待开始，复用学习结果 |
| `fc_monitor` | 待开始/已停止时更新跟踪、相位，不累计测量 |
| `fc_begin_measurement` | 锁定最近有效观测为起点，零计数，复用标定 |
| `fc_stop_measurement` | 锁定终点，后续最多4个有效观测仅确认此前数据 |
| `fc_push` | 提交测量帧，最多保留4个后续已处理观测用于确认 |
| `fc_finish` | 结束文件回放；片尾跨越仍待定时标记不完整 |
| `fc_interrupt` | 相机、几何或观测中断，冻结已确认累计值 |
| `fc_calibration_end` | 达到标定上限后明确记录初始化失败 |
| `fc_result` / `fc_row` | 固定数组的状态、实时诊断和本次已提交事件行 |

状态6为待开始；结果下标36为可开始标志，37为终点确认中，38为已锁定终点接收时间（相对测量未停止时为−1）。`fc_monitor`仅适用于待开始或完整的已停止状态；首次必须收到有效观测才能开始。停止后跟踪失效会使标定不可复用，小程序保留此前已经完成的测量记录。

结果布局见 `miniprogram/utils/counter.js`：包括状态、整数净计数、连续相位周期、完整标记、原因、缓冲帧数、五路归一化亮度、四路共同暗心零点相位、采样点坐标。旧文件回放模式保持原来的统一暗心物理边界。小程序经`fc_arm`和`fc_begin_measurement`进入起点相对模式：保留各路起点相位，由可信通道相位展开的中位数估计连续净周期，整数使用正负对称的整周期边界和0.02周期滞回。初始小幅反向不提前计一整圈，真正跨越与返回会增减。两种模式事件的发生时刻不必相同；物理暗心事件参考不能直接当作任意点击起点的整周期事件参考。事件同时记录发生帧/时间和确认帧/时间。正常逐帧回放最多延迟4帧；跳帧时是4个已处理观测，不能宣称等于4个原始曝光帧。

测量帧时间必须有限且递增。相邻有效观测间隔超过标定帧间隔中位数的3倍或0.2秒的较小值时，冻结可信计数并标记不完整。这是保守连续性门限，不证明门限以内不存在整周期混叠。跟踪失败、采样越界、有效相位对不足亦明确拒绝；初始化和测量状态须结合完整标记解读。失败段重新标定只能产生新段，不会补回丢失信息。

微信适配读取接口返回的RGBA宽高，按预览中心裁剪的aspect-fill几何映射圈选区域，再扩展为1.5倍带余量范围。源图起点取整后以计数偏移保留小数余量，标记位置包含半个面积采样单元；直接面积积分到96×96红通道。超出原始图像的余量按零填充；正式采样越界仍会拒绝，不通过坐标截断掩盖。相机帧尺寸变化、预览布局变化会中断当前段。预览裁剪模型需要手机对照验证，当前Iriun模拟器的尺寸测试不能证明所有手机的预览方向/裁剪都相同。

尝试可用的`performance.now()`/微信性能时钟，核对秒、毫秒、微秒或纳秒单位。官方小程序Performance类型未保证`now()`；真机/远程调试不可用、读数停滞或单位无法确认时，改用显式记录来源的`Date.now()`接收时钟。这个备用时钟不是保证单调的曝光时钟：每次读取检测倒退，核心保留真实间隔检查大幅前跳，异常中断测量，不夹紧时间或制造递增时间。小幅前跳仍无法与真实接收延迟区分。UI刷新单独使用墙钟，不参与计数。仅保留最新一个待处理RGBA帧，替换时保留新帧真实接收时间，间隔交由核心检查。长时间无帧亦标记中断。UI/曲线最多约10Hz刷新，核心仍逐个处理实际收到的可用观测；图表只用已收到的信号，不绘制预测未来。

构建固定Emscripten6.0.12，单线程、无SIMD、无完整OpenCV，WASM约80KiB，初始线性内存64MiB、最多128MiB。采用WASM异常处理以保留原算法的明确拒绝路径；当前开发者工具已验证，较旧手机微信运行时仍需兼容性验收。仅导入`env.emscripten_notify_memory_growth`；缓冲区视图每次按当前memory.buffer重建以适应内存增长。微信实际返回可能包装在`instance`字段，适配器兼容两种返回形式。

接口回放与拒绝测试：

```sh
.venv/bin/python tools/check_live_core.py
```

需按仓库原有说明准备原片和派生数据、CMake、FFmpeg、Node，并在`.tools/emsdk`安装/激活Emscripten6.0.12。新接口调用的是当前模型，不使用早期淘汰的WASM实现。

微信开发工具完整回放使用临时JSON帧块；二进制`.frc`直接读取曾被开发工具拒绝。准备后用wechatide的`automation_evaluate`调用当前页`verifyReplay("original")`或`verifyReplay("bilibili")`，随后读取`getApp()._coreVerification`。只调用已注册工具并按wechatide-skill完成环境门禁，刷新触发后需等页面真正就绪。验证函数只用于开发，不连接产品按钮：

```sh
.venv/bin/python tools/prepare_ide_replay.py
```

`miniprogram/verification/`中的临时JSON输入和期望行不提交Git，验证结束须清理，发布前不得保留。辅助比较器可以读取Native期望输出；正式计数核心不读取参考或答案。两段均已成为开发数据，B站人工真值仍未独立确认；桌面/开发者工具一致不能替代手机现场准确度、延迟、发热与曝光测试。

测量流程验证：`node tests/measurement_flow.cjs`（真实帧、Native/WASM状态对照），`node tests/measurement_page.cjs`（页面状态切换）。IDE复现：先运行前者，再运行`python3 tools/prepare_measurement_ide.py`，调用页面`verifyReplay("measurement-flow")`；验证时临时取消打包忽略verification文件夹，验证后恢复配置并移除临时目录。

帧流诊断：控制台`[STREAM]`记录首次相机回调尺寸、每秒接收/处理帧率、队列替换数、prepare/core/总处理耗时、标定开始结束与耗时、核心状态变化、350ms看门狗超时的原始差值、原生相机停止/错误。最多保留96条元数据，在中断时保存到`fringe-stream-debug`；长按状态按钮可复制JSON。日志不包含图像，不上传到服务端。当前仅增加证据，未放宽时间门限或改变计数数学。`tests/stream_diagnostics.cjs`复现了同步处理超过350ms后原看门狗可能误报的路径；真机是否为该原因仍需日志确认。
