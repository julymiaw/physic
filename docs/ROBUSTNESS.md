# 不破坏可信基线的鲁棒性开发

1. `main`和`self-recorded-v1`保留已通过自录开发参考的实现与证据；`adapt/bilibili`单独迭代，不自动合并。
2. 每次有效修改都由 `research/compare_scenes.py` 使用同一份C++实现回放两视频，核对事件、方向、净计数、完整覆盖和4帧确认约束。新增场景通过不能抵消旧场景退化，参数不能按视频名称分叉。
3. 自录按88个确定事件及用户认可的34秒局部歧义规则验收；B站暂按既有AI视觉参考的6个测量事件检查。这两个依据的可信程度不同，报告必须区分。
4. 两段视频现均为开发数据。要回答陌生场景是否有效，需要新增未参与修改的视频：预先固定圈选与标定规则，保存原片和独立参考，先跑冻结版本，再看结果；失败后用它修改模型，就将其转为开发数据并保留原失败记录。

当前证据支持“去除标定静态背景使B站初始化成功，且未破坏自录参考下准确度”，还不支持“所有手机、曝光、倾斜和速度都能工作”。扩展场景时继续报告初始化失败和不完整区间，不能以拒绝输出替代准确度验收。
