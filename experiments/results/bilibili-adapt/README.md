## 实际只改了什么

当前 `gradient_center` 原先直接用已对齐标定帧的空间梯度拟合二次相位中心。B站画面的固定纹理和明暗结构也贡献梯度，拟合中心因此受干扰。现在先计算标定帧每个像素的时间平均值，再从每张标定帧减去这张平均图，之后运行完全相同的梯度拟合：

`中心拟合输入(t) = 已对齐标定图(t) − 标定图的时间平均`

固定背景在相减后被抑制，变化条纹仍保留。B站中心从环心上方移回可见环心附近，梯度拟合残差从0.007130降为0.002817，随后同一套相位筛选规则选出了4路观测并完成计数。这一前后对照支持“静态背景污染中心拟合”这个解释，尚未证明其他因素不再影响其他视频。

**未改变**空间尺度、3×3采样块、最多5个采样位置、方向一致性门槛、相位零点规则或事件确认规则，没有B站专用阈值、中心坐标或错误时间补丁。标定时间和输入ROI是数据协议；测量期间没有新增背景扣除运算。只验证了这一项有效算法修改，不宣称数学意义上已经证明它是唯一或全局最少的修改。

## 证据与复现

- 基线标签 `self-recorded-v1` 保留原自录通过版本；`bilibili-transfer/` 保留其迁移失败记录。
- `summary.json` 记录当前实现指纹及两场景结果；两子目录保存逐帧、逐事件、检查点和截断结果。
- B站参考是早于当前算法输出保存的 `data/annotations/bilibili-provisional.json`。连续原片时空切片和所有10个原参考事件附近画面已复查；见 `review/`，没有按新算法的结果移动参考时刻。
- 两视频均已用于开发；后续修改不能再称B站为未见场景。陌生场景仍需另找未参与修改的新录像。
- 本轮没有运行WASM、合成测试或新性能验收；旧P95为基线计时，不冒充本分支测量。

准备原片及派生数据后，运行：

```sh
.venv/bin/python research/prepare_original.py
.venv/bin/python experiments/prepare_video.py bilibili
.venv/bin/python research/compare_scenes.py --name current
```

新结果写入忽略目录 `experiments/runs/paired/current/`，不会覆盖提交的基线或本次证据。脚本一次构建同一份Native实现，串行运行两场景并检查各自截断结果。冻结的B站失败可用 `research/check_bilibili_transfer.py` 从Git标签中的旧实现重新复现。
