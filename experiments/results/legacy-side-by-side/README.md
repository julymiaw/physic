# 本科轮廓法与当前相位法：同帧左右对比

[观看55秒对比视频](undergraduate-vs-current.mp4)。左侧为本科历史Python轮廓实现，右侧为当前Native C++相位实现；展示同一自录原片的相同帧、相同区域，保留各自中间结果及当时可用的计数。

旧代码直接取自Git历史提交 `c3ae479a0999f263b9365f1f94845e691e55d953` 中的 `轮廓检测.py`。其检测与状态机核心的AST与大四归档一致，差异仅为旧入口的视频文件名。此视频回放的是这份真实旧代码，没有重新实现或模仿旧方法，也不冒充大三C++版本的逐行回放。

## 比较规则

- 旧方法从原帧0开始、按4320×7680原始分辨率运行，使用历史默认参数：红通道分割、直方图阈值、二值化和形态学处理、圆形度筛选、同色轮廓面积变化投票、中心明暗切换计数。
- 仅替换视频读写：直接调用原 `ContourDetection.update`，避免历史视频驱动跳过首帧、重写输出帧率。观察钩子只记录原方法实际筛出的轮廓、位置与结果，不改变计算或状态。
- 新方法重新运行当前C++核心，其输出与已通过开发验证的结果逐字节一致。保持9.6–11.6秒标定、64像素计数坐标和96像素带余量跟踪输入。
- 对比段为原帧279–1436，11.632622–59.831322秒，1158帧全部逐帧展示。左右严格使用同一原始帧，没有逐事件平移时间或修改输出值。
- 旧状态机不中途重置。共同起点前原累计为7，左侧显示 `旧原累计−7`，并同时列出原累计值；新侧显示收到当前帧时已经确认的计数，最多滞后4帧。
- 两侧计圈边界和确认机制不同，短时差值不能直接当成错误。片尾两侧均为84圈，也不能证明事件完全一致。视频保留29秒、45.6秒、51.25秒及34秒歧义附近的提示。
- 圆环线条来自旧算法真实筛选结果，只在展示时加粗。显示图缩小不影响旧算法的原分辨率输入。视频按24 fps离线同步播放，不能据此比较实际处理速度；Python/C++及两种输入分辨率也不构成受控算速比较。

|---|---:|---:|
| 加一事件 | 86 | 87 |

新方法包含34秒用户接受的一对可选往返。两组事件不能只凭总数配对；本视频用于查看原处理过程与局部分歧，不重新定义真值。

## 结果与复现

`old-frames.csv` 保存旧方法全部1437帧的原始累计、状态和检测信息；它们与此前完整旧算法回放逐帧一致。`comparison.csv` 保存对比段1158帧的旧累计、相对累计、新发生时间轴和新确认时间轴。`manifest.json`记录源代码、原片、新实现和视频指纹，以及同步和编码检查结果。

准备原始录像和冻结派生输入后运行：

```sh
.venv/bin/python -m pip install -r requirements-legacy.txt
.venv/bin/python research/render_legacy_comparison.py
```

脚本从Git历史读取旧源码，本地归档保持原样。需要完整Git历史、FFmpeg和C++17构建环境；旧源码不重新放回当前算法目录。该对比工具单独使用旧方法所需SciPy、tqdm，当前C++核心没有新增依赖。
