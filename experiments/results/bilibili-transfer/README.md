# 当前算法对B站视频的迁移检查

**结论：当前版本不能直接有效计数。** 它在标定阶段明确报 `insufficient phase pairs`，没有开始测量。计数有效覆盖率为0，不能给出可信净计数或逐事件准确率；这不是把拒绝当成准确计数通过。

本次保持自录版本的跟踪、中心拟合、相位候选和计数规则不变，未按B站结果调参。输入使用先前人工圈定的光屏区域 `[284,0,164,180]`（640×360派生画面），加余量至96像素跟踪图，64像素计数坐标不变。画面顶部之外明确补黑，不宣称恢复不可见内容。Native回放只增加了可设置坐标偏移的输入选项，自录默认回放输出与原通过版本逐字节一致。

标定固定采用原片开头256帧（0–8.5秒），没有另挑容易的片段。原自录9.6–11.6秒是该录像的人工指定时间，不能照搬给变化更慢的另一段视频。B站待测段为8.533333–21.2秒，共381帧；标定失败后没有继续猜测它们的计数。

| 检查 | 实际结果 |
|---|---|
| 视频 | 637帧，30 fps，21.2秒时间轴 |
| 独立轮廓跟踪回放 | 全637帧通过现有质量门槛；补偿后轮廓IoU中位0.9931 |
| 计数器内标定跟踪 | 前256帧全部通过 |
| 候选信号 | 120个位置组合；51组对比度足够；0组合格 |
| 失败门槛 | 51组的方向一致性均低于0.9；最高0.820531 |
| 其他门槛 | 43组净角度推进至少1.5周期；30组通过最小轨迹半径要求；缺少周期数不是唯一原因 |
| 最佳被拒绝候选 | 净角度推进约3.58周期；一致性为净推进量／总角度变化量，局部折返拉低评分 |
| 输出状态 | 初始化失败，无有效计数；不能把“没有输出事件”解释为视频里没有周期变化 |

这里区分了**跟踪质量门槛通过**与**独立证明每帧物理配准准确**。前者已有证据，后者未做人工逐帧验证。通过跟踪也没有解决计数初始化。

原画面中静态纹理和散斑很强。诊断图里的拟合中心偏向环心上方，提示空间梯度中心估计可能受纹理影响；中心／辅助亮度也出现非平滑波形。中心偏差、散斑与信号模型各自贡献尚未通过隔离实验确认，不能直接断言只调低门槛就能解决。

**下一步应先校准干涉中心，再检查对齐图像是否含稳定的共同相位。** 这比直接放宽方向筛选更能解释失败；本次仅完成固定版本的迁移检查，没有把B站视频调成通过，也没有运行WASM或合成测试。

证据：`protocol.json`记录测试前规则、输入及实现指纹；`replay.log`记录初始化失败；`calibration-diagnostic.txt`记录每个对比度足够候选的判据；`motion.csv`为独立跟踪逐帧结果；`result.json`为汇总；`failure-overview.jpg`展示真实画面和被拒绝候选的亮度／角度轨迹。旧的B站视觉标签没有供算法读取，也没有被当成本次计数真值。

复现：在项目根目录运行 `.venv/bin/python research/check_bilibili_transfer.py`。脚本核对冻结实现和输入指纹，生成真实小图回放，再编译、回放和绘制诊断；预期结果是标定失败。未来修改算法前应保留此基线，不覆盖失败证据。
